# Non-standard Next.js — docs are error-triggered, not upfront reading

This project's Next.js has breaking changes vs. the version in most models' training data — APIs, conventions, and file structure may differ.

**Do not read `node_modules/next/dist/docs/` preemptively.** Docs live there (path resolved relative to this file's location, since in monorepos `next` may not be hoisted to the repo root) but reading them costs real tokens on every session, and most of the time your training-data knowledge of Next.js is close enough to work fine.

Only open the docs when one of these actually happens:
- A build/runtime error references a Next.js API, config key, or file convention.
- Generated code doesn't behave as expected (wrong route match, config ignored, unexpected warning) and standard Next.js knowledge doesn't explain why.
- You hit a deprecation warning in the console/build output.

When you do read the docs, read only the specific page relevant to the error/symptom — not the whole docs tree.

This block is regenerated by `next dev` (see `node_modules/next/dist/server/lib/generate-agent-files.js`). Committing it keeps the tree clean; deleting it just brings it back uncommitted.
